# Project Specification

## Problem and users
Merchants lose revenue through failed payments, lapsed subscriptions, unpaid invoices, abandoned checkouts, and poorly timed recovery. Future operators and reviewers need a system that can explain what happened and why.

## Goals
Create a controlled system that detects risk, gathers context, uses AI only for bounded contextual reasoning, validates decisions deterministically, executes permitted tools, verifies outcomes, and audits the lifecycle.

## Phase 1 scope
This phase establishes the repository, backend/frontend skeletons, configuration, logging, tests, documentation, ADRs, and future boundaries.

## Non-goals
No real-money processing, Razorpay production integration, autonomous communication, financial recovery action, full auth, complex dashboard, production claim, fabricated data, or Phase 2 implementation.

## Acceptance criteria
The repository is runnable, documented, tested, secret-safe, structurally ready for Phase 2, and explicitly clear about what is implemented versus future.
